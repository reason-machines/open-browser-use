# Online-Mind2Web subset audit (run baseline-v2, 2026-10-15)

Why did both agents score so low on the Mind2Web subset, when Aside reports 297/300 (99%) on the full set?
Each of the 20 tasks was audited by `bench/m2w_audit.py` (codex gpt-6.1-sol, JSON schema). The auditor saw the task, the WebJudge key points, every arm's verdict, judge reason and final answer, anti-bot markers grepped from the raw logs, and Aside's own public result for the same task id ([at-inc/aside-benchmarks](https://github.com/at-inc/aside-benchmarks), gpt-5.5, thinking high, start URL given, 900 s timeout).

## Findings

1. **The tasks are feasible today.** 19/20 were judged doable on today's site; 1 is unclear (a PhET simulation). Nothing was dropped as stale.
2. **The missing start URL was the biggest protocol bug: it plausibly caused failures in 9/20 tasks.** The gated HF dataset carries a `website` field that our first task file lacked, so agents had to search for the site or answered from general web search. The website and level are now restored from a public mirror (browserbase/stagehand `onlineMind2Web.jsonl`), and every prompt ends with `Start from <website>` as in the official harness.
3. **The judge was first starved of evidence, then fixed.** v1 showed only the last 80 trajectory entries with tool results clipped to 1,500 characters, so most failures read "not visible in the trajectory". The judge now gets the full trajectory, with results clipped at 8,000 characters and 240k characters in total, re-parsed from the raw logs, plus a WebJudge-style rule (key points, actions plus observations as evidence). After that fix the auditor flagged only 2 task(s) as possibly over-strict.
   - Score progression on the same trajectories: aside 3 → 7 → 8/20 and ours 1 → 3 → 4/20 (v1 judge → full evidence → WebJudge rule).
4. **Anti-bot and region walls were rare.** They appeared in 3 task(s): m2w-0a0fa834 (aside), m2w-39c388cd (aside), m2w-0b2623e9 (ours). The San Francisco IP was not an issue.
5. **Aside's run here differs from its published configuration.** We ran both agents at medium effort, where Aside published thinking high. With medium effort Aside's agent often answered in 1–3 steps from web search instead of working the site (median 3 steps). We keep both agents at medium effort and on the same model (gpt-6-luna) for fairness.
6. **Under a fair protocol the auditor estimates aside 7/20 and ours 3/20** on these v2 trajectories. The remaining gap to Aside's published number comes from the start URL, the effort level, and real execution failures, which feed the build backlog.

## Changes made

- `tasks/mind2web.json` now carries the official `website`, `level` and `reference_length`. Prompts end with `Start from <website>`.
- The judge uses full evidence and a WebJudge-style rule (`runner.py:judge`).
- `--rejudge` re-parses the raw logs, so improvements to the judge apply to old runs.
- `meta.json` records `prompt_given`, so re-judging an old run shows the prompt the agent actually received.
- Mind2Web is re-run with start URLs for every arm in `baseline-v3`.
